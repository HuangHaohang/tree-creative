# Security Policy

## Reporting a Vulnerability

Do not disclose vulnerabilities through public issues, pull requests, discussions, screenshots, or logs.

Use GitHub's private vulnerability reporting for this repository when enabled. Until a dedicated security contact is recorded, notify the repository owner through an approved private channel.

Include only the information needed to reproduce and assess the issue:

- Affected component and version or commit.
- Impact and realistic attack scenario.
- Reproduction steps or a minimal proof of concept.
- Suggested mitigation, if known.
- Whether credentials or production data may be exposed.

Do not access, modify, retain, or exfiltrate data beyond the minimum required for authorized validation.

## Response Principles

- Restrict details to the smallest necessary response group.
- Preserve evidence without committing secrets or sensitive data.
- Prioritize containment, correction, verification, controlled disclosure, and post-incident learning.
- Rotate exposed credentials and audit related activity whenever compromise is possible.

## Supported Versions

Security fixes target the production release and the default branch unless a release policy explicitly states otherwise.
