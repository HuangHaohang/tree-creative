# 开发八荣八耻

> 每次前后端开发前必读。代码首先写给人维护，其次才是给机器执行。

1. 以开放扩展、关闭修改为荣，以牵一发而动全身为耻。
2. 以高内聚、低耦合为荣，以职责混杂、层层纠缠为耻。
3. 以边界清晰、前后端分治为荣，以逻辑混写、巨石堆砌为耻。
4. 以模块拆分、单一职责为荣，以万能文件、万能函数为耻。
5. 以成熟轮子、合理复用为荣，以重复造轮子为耻。
6. 以消除重复、沉淀能力为荣，以复制粘贴、四处散落为耻。
7. 以自动测试、持续验证为荣，以手工侥幸、带病交付为耻。
8. 以简单清晰、易于维护为荣，以炫技晦涩、堆成屎山为耻。

## 落地底线

- 前端与后端必须物理分离，并在各自内部按业务或职责分模块；禁止跨层堆写和巨型文件。
- 新需求优先通过新增实现或适配器扩展稳定接口，不为方便随意侵入、复制或耦合已有模块。
- 实现通用能力前先查找现有代码与成熟依赖；选择维护活跃、安全、兼容的轮子，并封装好项目边界。
- 每次改动都必须有与风险相称的自动化验证；发现结构开始腐化时，在本次范围内及时收敛。
